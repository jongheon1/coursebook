## 1. 문제 정의 — Maximum Subsequence Sum

정수 수열 $a_1, \dots, a_n$이 주어졌을 때, **연속 부분수열(contiguous subsequence)의 합 중 최댓값**을 구하는 문제. 공집합도 합이 0인 유효한 부분수열로 인정한다(따라서 답은 항상 $\ge 0$).

판서 예시 수열: `0 100 -50 -60 30 -10 40 45 -3 1`

강의 중 구두로 든 예: 부분수열 `40, -10, 45`를 고르면 합은 $40 + (-10) + 45 = 75$인데, 이건 최선이 아니다. 실제 최선은 뒤쪽의 `40`부터 `45`까지 구간으로, 총합이 $110$이다.

**문제 정의 명확화 (교수가 직접 짚은 애매한 지점)**: "만약 주어진 숫자가 전부 음수라면 어떻게 하나?"라는 질문이 나올 수 있다. 이때 (a) 그냥 최댓값 하나만 반환할지, (b) 공집합을 부분수열로 인정해서 답을 0으로 할지 두 가지 선택지가 있는데, 이 수업에서는 **공집합을 유효한 부분수열로 인정**하고 그 합을 0으로 정의하기로 한다. 이게 이 문제의 완전한 정의다.

## 2. Alg 1 — 가장 단순한 정의 그대로

```
sol ← 0
for each i, j with 1 ≤ i ≤ j ≤ n do
    if Σ_{k=i}^{j} a_k > sol then
        sol ← Σ_{k=i}^{j} a_k
return sol
```

sol을 0으로 초기화하는 이유: 0 자체가 이미 하나의 유효한 답(공집합)이기 때문. "프로그래밍 수업을 들어봤다면 이 알고리즘 자체는 자명할 것"이라는 언급과 함께 제시.

## 3. 수업 중 상호작용 — "실행 시간이 얼마인가?" 질문과 Alg 2로의 전환

Alg 1을 제시한 뒤 교수가 학생들에게 직접 질문을 던졌다: **"이 알고리즘의 실행 시간이 얼마인가?"** 학생들이 답을 외쳤고, 교수는 "다들 동의하나요? 다른 답 있는 분?"이라고 되물었다. 교수는 대부분의 학생이 $O(n^3)$ 또는 $O(n^2)$로 답했을 거라 추측하며, **둘 다 합리적인 추측**이라고 인정했다.

하지만 교수는 이 질문이 그 시점에서는 **공정하지 않았다**고 스스로 지적했다 — 아직 구현 세부사항(특히 부분합을 어떻게 계산하는지)을 명시적으로 밝히지 않았기 때문이다. 그래서 그 세부사항을 전부 드러내도록 알고리즘을 다시 쓰겠다고 하며 Alg 2로 넘어간다.

## 4. Alg 2 — Alg 1을 명시적인 3중 루프로 재작성

```
sol ← 0
for i ← 1,…,n do
    for j ← i,…,n do
        sum ← 0
        for k ← i,…,j do
            sum ← sum + a_k
        if sum > sol then
            sol ← sum
return sol
```

Alg 1에서 그냥 "부분수열 합을 계산한다"고 한 줄로 뭉뚱그렸던 부분이, 사실은 그 자체로 또 하나의 루프(`sum`을 0으로 초기화하고 $k$를 $i$부터 $j$까지 돌며 $a_k$를 누적)라는 점을 명시적으로 보여주는 것이 이 재작성의 핵심.

**Theorem 1.** Alg 2 runs in $O(n^3)$ time.

*Proof.* 기본 연산 수는
$$\sum_{i=1}^{n} \sum_{j=i}^{n} (j-i+1)$$
에 비례한다. $j' = j-i+1$로 치환하면 $\sum_{i=1}^n \sum_{j'=1}^{n-i+1} j'$가 되고, $i' = n-i+1$로 다시 치환해서 정리하면
$$\frac{n(n+1)(n+2)}{6} = \Theta(n^3)$$
이 됨을 귀납법으로 보일 수 있다 (유도의 뒤에서 두 번째 단계가 귀납법으로 증명하는 부분). 교수는 "오늘이 첫 강의라 필요한 것보다 좀 더 자세히, 전체 분석을 다 짚어보겠다"고 명시적으로 밝히며 이 유도를 전부 칠판에 전개했다.

## 5. Alg 1/2보다 나을 수 있는가? — 중복 계산 찾기

**핵심 질문**: $O(n^3)$보다 asymptotically 더 나은 시간에 풀 수 있는가?

**핵심 관찰**: Alg 1/2에서 부분합을 어떻게 계산하느냐에 따라 같은 알고리즘(Alg 1)이 삼차 시간으로도, 이차 시간으로도 구현될 수 있다. 예를 들어 $i=2, j=10$일 때 $a_2 + a_3 + \dots + a_{10}$을 계산하고, 바로 다음 반복인 $i=2, j=11$에서 $a_2 + \dots + a_{11}$을 계산한다 — **직전 합의 거의 전부를 처음부터 다시 계산**하고 있는 것이다.

교수가 명시적으로 제시한 **알고리즘 설계 원칙**: 어떤 순진한(naive) 해법에서 시작한 다음, 그 실행 과정에 **중복 계산이 있는지** 물어보고, 있다면 그걸 **체계적으로 제거할 방법**이 있는지 물어보라. 여기서는 가능하다 — 다음 반복에서 이전에 계산해둔 값을 재사용하고 원소 하나만 더하면 새 부분합을 상수 시간에 얻을 수 있다.

## 6. Alg 3 — 누적합(prefix-sum) 방식으로 $O(n^2)$

```
sol ← 0
for i ← 1,…,n do
    sum[i, i-1] ← 0
    for j ← i,…,n do
        sum[i, j] ← sum[i, j-1] + a_j
        if sum[i, j] > sol then
            sol ← sum[i, j]
return sol
```

$\mathrm{sum}[i,j]$를 직전 반복에서 이미 계산된 $\mathrm{sum}[i,j-1]$에 $a_j$ 하나만 더해서 얻는다. 시작값이 필요한데, $\mathrm{sum}[i,i-1]$은 단순히 0으로 초기화한다.

**러닝타임 유도의 인덱스 치환 보충**: Theorem 1과 같은 방식의 유도를 Alg 3의 안쪽 루프에도 적용하며, $j-i+1$을 다시 $j'$로 치환한다. $j$가 $i$부터 $n$까지 도므로, $j'$는 $i-i+1=1$부터 $n-i+1$까지 도는 것 — 같은 범위를 이름만 바꿔 부른 것이라고 교수가 짚었다.

**Theorem 2.** Alg 3 runs in $O(n^2)$ time. (이중 루프뿐이므로 자명하다며 별도 증명은 생략.)

## 7. Alg 3의 정확성 증명

**Theorem 3.** Alg 3 is correct.

*Proof.* 교수는 "알고리즘이 올바르다는 걸 증명하려면 **두 가지**가 필요하다"고 먼저 짚었다: (1) 종료된다면 올바른 답을 낸다는 것, (2) 실제로 종료한다는 것. Theorem 2에서 이미 이차 시간에 동작함을 알고 있으므로 **종료성은 자동으로 확보**된다. 따라서 남은 건 "종료한다고 가정했을 때 올바른 답을 낸다"는 것만 보이면 된다.

알고리즘의 동작을 보면, 반환값은
$$\max\big(\{\,\mathrm{sum}[i,j] \mid 1 \le i \le j \le n\,\} \cup \{0\}\big)$$
이다(초기값 0도 후보 중 하나로 포함). 그런데 여기서 교수는 한 가지 미묘한 지점을 짚었다: $\mathrm{sum}[i,j]$는 **알고리즘 안 변수의 이름일 뿐**이다 — 원칙적으로 어떤 값이든 담을 수 있다. 우리가 실제로 보여야 하는 건, 그 변수가 이름이 암시하는 대로 **실제 부분합 $\sum_{k=i}^j a_k$과 같은 값을 담고 있다**는 것이다. 이게 다음 Claim이다.

**Claim 1.** 모든 $1 \le i \le j \le n$에 대해 $\mathrm{sum}[i,j] = \sum_{k=i}^{j} a_k$.

*Proof (induction on $j-i$).* $l \ge 0$마다 술어 $P(l)$을 정의한다 — "$j-i=l$을 만족하는 모든 $i,j$에 대해 $\mathrm{sum}[i,j]$가 부분합과 같다." $P(0), P(1), P(2), \dots$가 전부 성립함을 보이는 것이 "$j-i$에 대한 귀납법"의 의미다.

- **Base case** ($j-i=0$): $\mathrm{sum}[i,i] = \mathrm{sum}[i,i-1] + a_i = 0 + a_i = \sum_{k=i}^{i} a_k$.
- **Induction step**: $j-i=\ell_0$에서 성립한다고 가정. $j-i=\ell_0+1$일 때,
$$\mathrm{sum}[i,j] = \mathrm{sum}[i,j-1] + a_j = \Big(\sum_{k=i}^{j-1} a_k\Big) + a_j = \sum_{k=i}^{j} a_k. \qquad \blacksquare$$

**참고 (녹음 기준)**: $\mathrm{sum}[i,i-1]$이라는 변수 이름 자체가 "$a_i$부터 $a_{i-1}$까지의 합"을 의미해야 할 이유는 없다고 교수가 명시적으로 짚었다 — 그냥 변수 이름이고 0으로 초기화된 값일 뿐이며, Claim 1은 $j \ge i$인 경우만 다룬다.

## 9. Alg 4 — 분할정복(merge sort 방식) 시도

Alg 1→2→3의 교훈("중복 계산을 찾아 제거하라")에 이어, 교수는 효율적 알고리즘을 설계하는 **또 다른 도구로 재귀(recursion)**를 제시했다. "자료구조 수업에서 이미 재귀 알고리즘을 적어도 하나(merge sort)는 봤을 것"이라며, 그 구조를 흉내 내보자고 제안.

**Merge sort 구조 복습(교수의 설명)**: 정렬할 수열을 왼쪽/오른쪽 절반으로 나누고, 각 절반을 재귀적으로 정렬한다 — 즉 원래 풀려던 것과 똑같은 문제를 더 작은 두 조각에 대해 푸는 것. 그다음 두 재귀 호출의 결과를 이용해 원래 문제의 답을 얻는 게 merge sort의 "합치는(merge)" 단계다. 이 문제에서도 같은 접근을 쓴다: 수열을 두 절반으로 나누고, 각 절반에 대해 재귀적으로 최대 부분수열 합을 구한 다음, 그 두 답을 이용해 전체 답을 얻는다.

```
function MSS(s, t):        # a[s..t]의 최대 부분수열 합을 반환
    if s == t:
        return max(a[s], 0)     # 기저 사례: 원소가 a[s]가 음수일 수 있으므로 0과 비교
    m ← midpoint(s, t)
    solutionLeft  ← MSS(s, m)
    solutionRight ← MSS(m+1, t)
    return max(solutionLeft, solutionRight)

# main: return MSS(1, n)
```

기저 사례에 대해 교수가 직접 질문했다: "$s=t$일 때, 즉 원소 하나 $a_s$뿐일 때 답이 그냥 $a_s$인가? 이게 정말 맞나? 언제 틀리는가?" — 답: $a_s$가 음수일 때 틀리고, 그럴 때 올바른 답은 0이다. 그래서 $\max(a_s, 0)$을 반환한다.

재귀 사례는 merge sort와 동일한 구조: 중간점 $m$을 계산하고 $[s,m]$, $[m+1,t]$에 대해 각각 재귀 호출한 뒤 더 나은 쪽을 반환한다. 본체는 전체 범위 $[1,n]$에 대해 이 함수를 호출한다.

**"이 알고리즘이 맞는가?"** — 교수가 직접 질문을 던지고 스스로 답했다: **아니다, 틀렸다.** 왜 틀렸는지, 무엇이 문제인지는 **그 자리에서 밝히지 않았고**, "오늘 원래 계획했던 시간보다 이미 넘겼다"며 **학생들이 집에 가서 생각해보고 다음 강의(금요일)에 바로 이 지점부터 이어가겠다**고 마무리했다.

## 10. 수업 중 퀴즈

시간이 남아 진행한 퀴즈(`quiz-01.jpeg`, CSI 3108 Fall 2026 표기). 교수가 밝힌 목적: **채점하지 않고, 학생들이 선수지식(증명 기법)을 갖췄는지 확인하기 위함**. 이름·학번 기재는 선택(채점 안 하므로). 풀이는 훑어보지만 점수 형태의 피드백은 없다고 명시.

**(1)** $a_1,\dots,a_n \in \mathbb{Q}$ ($n \ge 2$)이고 $a_1 < a_n$이면, $a_i < a_{i+1}$인 $i \in \{1,\dots,n-1\}$이 존재함을 증명하라.
- 판서/필기에 남은 학생 풀이 시작 부분: "그런 $i$가 존재하지 않는다고 가정하면" — 귀류법/대우법으로 진행하려던 것으로 보이나, 이후 전개는 기록되지 않았다.

**(2)** 정점이 2개 이상인 모든 simple graph에는 차수(degree)가 같은 서로 다른 두 정점이 반드시 존재함을 증명하라.
- 답안 기록 없음.

**2일차(09-04) 공개된 정식 풀이** — 교수가 직접 공개 풀이를 칠판에서 설명했고(LearnUs에도 별도로 게시 예정이라고 언급), 제출 통계도 함께 공개했다: (1)은 학생 30% 이상이 정답/거의 정답, (2)는 20% 이상 — "두 번째가 더 어려웠던 것 같다"는 코멘트.

- **(1) 풀이.** 뭔가를 증명하기 전에 먼저 반례를 시도해서 직관을 얻는 접근을 시연했다: $n=10$, $a_1=3$, $a_{10}=10$이라 하고 그런 $i$가 없도록 수열을 채워보려 하면, $a_2 \le 3$, $a_3 \le 2$, … 매번 값이 감소하거나 유지될 수밖에 없어 $a_9$에 이르면 처음 값($a_1=3$)보다 클 수 없다 — $a_1 < a_n$에 모순. 이로부터 귀류법이 맞는 접근임을 확인하고 정식 증명: 그런 $i$가 없다고 가정하면 모든 $i$에서 $a_i \ge a_{i+1}$이므로 $a_1 \ge a_2 \ge \dots \ge a_n$, 즉 $a_1 \ge a_n$ — $a_1 < a_n$과 모순. $\blacksquare$ (표준 풀이 방향과 일치.)
- **(2) 풀이.** 그래프가 simple이므로 모든 정점의 차수는 $0$부터 $n-1$ 사이($n$ = 정점 수). 만약 $0$부터 $n-1$까지 $n$개 값이 전부 실제로 나타난다면 그게 반례 후보지만, 차수 $n-1$인 정점(모든 정점과 인접)과 차수 $0$인 정점(어떤 정점과도 비인접)은 동시에 존재할 수 없다 — 그러므로 $n$개 가능값 중 최소 하나는 비어 있어, 실제 등장 가능한 차수값은 최대 $n-1$개인데 정점은 $n$개다. 비둘기집 원리로 차수가 같은 두 정점이 존재. $\blacksquare$ (표준 풀이 방향과 일치.)

# Day 2 (2026-09-04) — Alg 4 정정부터 Closest Pair 도입까지

## 11. Alg 4가 틀린 이유, 그리고 Algorithm 5 (경계를 처리하는 $O(n\log n)$ 알고리즘)

**왜 Alg 4(§9)가 틀렸는가.** `solLeft`, `solRight`는 각각 왼쪽/오른쪽 절반에 대한 정답이라고 그냥 가정한 값일 뿐이다. 그런데 전체 구간 $[s,t]$에 대한 진짜 답은 세 가지 중 하나다: (1) 완전히 왼쪽 절반 안에 있음 → `solLeft`가 맞다, (2) 완전히 오른쪽 절반 안에 있음 → `solRight`가 맞다, (3) **경계($a_m$과 $a_{m+1}$ 사이)를 가로지름** → 이 경우 답은 `solLeft`도 `solRight`도 아니다. Alg 4는 그냥 두 값 중 더 큰 걸 반환하므로 세 번째 경우를 완전히 무시한다 — 이게 반례가 존재하는 근본 이유다.

**나이브한 수정과 그 한계.** 경계를 포함하는 부분수열의 시작 인덱스($[s,m]$ 범위)와 끝 인덱스($[m+1,t]$ 범위)를 전부 열거하면 첫 호출(길이 $n$)만으로도 $\sim (n/2)^2 = O(n^2)$가지 경우의 수가 나온다. 이미 $O(n^2)$짜리 알고리즘(Alg 3)이 있는 마당에 재귀의 첫 호출부터 이 비용을 낸다면 개선의 여지가 없다.

**핵심 관찰.** 경계를 포함해야 한다는 제약이 있을 때, 답은 정확히 그 경계에서 끝나는 최대 부분수열과 정확히 그 경계에서 시작하는 최대 부분수열을 이어붙인 것과 같다 — 둘 중 하나라도 국소 최댓값이 아니면 그 부분을 국소 최댓값으로 바꿔치기해서 항상 더 좋거나 같은 답을 얻을 수 있기 때문이다.

**Algorithm 5** (두 재귀 호출 이후 실행):

```
subsolLeft ← 0
for i ← m, m-1, …, s do          # 경계에서 끝나는 최대 부분수열
    partial ← Σ_{k=i}^{m} a_k     # 이전 partial에서 O(1) 갱신 (Alg 3와 동일한 트릭)
    if partial > subsolLeft then subsolLeft ← partial

subsolRight ← 0
for i ← m+1, …, t do              # 경계에서 시작하는 최대 부분수열
    partial ← Σ_{k=m+1}^{i} a_k
    if partial > subsolRight then subsolRight ← partial

return max(solLeft, solRight, subsolLeft + subsolRight)
```

인덱스 $i$를 $m$에서 $s$ 방향으로 **감소시키며** 도는 이유는 Alg 3와 똑같은 이유다 — partial sum을 매번 처음부터 계산하지 않고 이전 값에 원소 하나만 더해 $O(1)$에 갱신하기 위해서다. 그래서 이 병합(merge) 단계는 $O(t-s+1)$ 시간에 끝난다.

**시간복잡도.** "재귀 호출 두 번 + 선형 시간 병합"이라는 구조가 merge sort와 완전히 동일하므로, 풀고 있는 문제는 다르지만 시간복잡도는 같아야 한다 — Algorithm 5는 $O(n\log n)$. Alg 3의 $O(n^2)$에서 유의미한 개선.

## 12. "소원 빌기(wishing)"에서 $O(n)$ 알고리즘으로

**사고 실험.** 만약 "답이 반드시 $a_{10}$과 $a_{11}$ 사이 경계를 포함한다"는 정보를 (어디서 왔는지 몰라도) 미리 안다면, §11의 병합 단계에서 $m$을 10으로 고정해서 실행하기만 하면 $O(n)$에 답이 나온다. 즉 **경계 위치를 안다면 선형 시간으로 충분하다**.

**Algorithm 6 (알고리즘이 아님)**: (1) $a_m$-$a_{m+1}$ 경계가 답에 포함되도록 하는 $m$을 마법처럼 소원 빈다, (2) 그 경계에서 끝나는 최대 부분수열을 구한다, (3) 그 경계에서 시작하는 최대 부분수열을 구한다, (4) 둘의 합을 반환한다. "소원 빌기"가 알고리즘의 한 단계로 허용되지 않으므로 이건 진짜 알고리즘이 아니다.

**대체 전략**: 원하는 정보를 모른다면, 그게 될 수 있었던 모든 가능성을 다 시도하고 최선을 고른다. 경계는 $1,\dots,n-1$ 중 하나이므로, $n-1$가지를 전부 시도.

**Algorithm 7**:

```
for m ← 1, …, n-1 do
    subsolLeft[m]     ← max({ Σ_{k=i}^{m} a_k | 1 ≤ i ≤ m } ∪ {0})       # 경계 m에서 끝나는 최대 부분수열
    subsolRight[m+1]  ← max({ Σ_{k=m+1}^{i} a_k | m+1 ≤ i ≤ n } ∪ {0})   # 경계 m에서 시작하는 최대 부분수열

sol ← 0
for m ← 1, …, n-1 do
    if subsolLeft[m] + subsolRight[m+1] > sol then
        sol ← subsolLeft[m] + subsolRight[m+1]
return sol
```

나이브하게 구현하면 $O(n)$번 반복 $\times$ $O(n)$가지 경우 $\times$ partial sum 계산 $O(n)$ = $O(n^3)$. Alg 3에서 썼던 누적합 트릭을 다시 쓰면 $O(n^2)$까지는 쉽게 내려간다 — "이 모든 노력 끝에 또 다른 $O(n^2)$ 알고리즘을 얻었다"는 게 교수의 코멘트. 하지만 이 트릭만으로는 $O(n)$에 도달할 수 없다 — 매 반복마다 여전히 선형 개수의 서로 다른 partial sum을 봐야 하기 때문이다.

## 13. $O(n)$으로: `subsolLeft`들 사이의 재귀 관계

**관찰.** $\mathrm{subsolLeft}[m]$과 $\mathrm{subsolLeft}[m-1]$ 사이에는 다음 관계가 성립한다 (모든 $m>1$에 대해):
$$\mathrm{subsolLeft}[m] = \max(\mathrm{subsolLeft}[m-1] + a_m,\ 0)$$

**증명(강의에서 구두로 제시).** $\mathrm{subsolLeft}[m]$이 0이 아니라면 그 최적 부분수열은 공집합이 아니고, 경계 $m$에서 끝나야 하므로 반드시 $a_m$을 포함한다. $a_m$을 포함한다면 나머지 부분은 그 앞 경계($m-1$)에서 끝나는 최대 부분수열이어야 한다 — 그렇지 않으면 그 부분을 $\mathrm{subsolLeft}[m-1]$로 바꿔치기해서 더 좋은 답을 얻을 수 있기 때문이다. 0인 경우는 별도로 처리(공집합을 택하는 경우).

**이 관계의 의미.** $\mathrm{subsolLeft}[1] = \max(a_1, 0)$에서 시작해서, $\mathrm{subsolLeft}[2]$는 $\mathrm{subsolLeft}[1]$에서, $\mathrm{subsolLeft}[3]$은 $\mathrm{subsolLeft}[2]$에서 — 이렇게 각 항을 $O(1)$에 구할 수 있으므로 **왼쪽 subsolution 전체를 선형 시간에 계산**할 수 있다. 대칭성에 의해(방향만 뒤집으면 됨) 오른쪽 subsolution도 오른쪽에서 왼쪽으로 선형 시간에 계산된다 — 단 두 번의 별도 for 루프가 필요하다(왼쪽은 왼→오, 오른쪽은 오→왼으로 계산되므로). 여기에 §12 Algorithm 7의 마지막 결합 루프(선형)를 더하면 **Algorithm 7 전체가 선형 시간**에 돈다. $O(n^2)$처럼 보이는 의사코드만 봐서는 이게 명확하지 않다는 게 교수의 코멘트.

## 14. 더 단순한 선형시간 알고리즘 — `MaxEndingAt` (Kadane's algorithm)

교수는 §13의 선형시간 버전을 완전히 자세히 다루지 않았는데, 이유는 **훨씬 단순한 버전**이 있기 때문이다. §12의 "소원 빌기"를 다시 보면: 경계를 답에 "포함된" 위치로 소원 빌 게 아니라, 답의 **끝**을 표시하는 경계로 소원 빌면 `subsolRight`가 통째로 필요 없어진다. 단, 이제는 내부 경계가 아니라 "끝"을 표시하므로 수열이 맨 끝($a_n$)에서 끝나는 경우 하나가 추가로 필요해 $n-1$가지가 아니라 $n$가지 경우를 본다.

Algorithm 7에서 `subsolRight` 관련 줄을 전부 지우고, 더 이상 "왼쪽"이라는 이름이 의미 없어지므로 변수명을 `MaxEndingAt`으로 바꾼 것이 최종 알고리즘이다:

```
MaxEndingAt[1] ← max(a_1, 0)
for m ← 2, …, n do
    MaxEndingAt[m] ← max(MaxEndingAt[m-1] + a_m, 0)

sol ← 0
for m ← 1, …, n do
    if MaxEndingAt[m] > sol then sol ← MaxEndingAt[m]
return sol
```

**직관(교수가 "이게 처음 보여준 알고리즘이라고 생각하고 보라"며 재서술)**: 왼쪽부터 스캔하면서, 현재 위치에서 정확히 끝나는 최대 부분수열을 계속 유지한다 — 지금까지의 최댓값에 새 원소를 더하거나, 그 원소가 너무 나쁘면(누적값이 음수가 되면) 공집합으로 리셋한다. 끝까지 돌면서 본 최댓값이 답이다. (수업 중 질의응답: "누적값이 음수가 되면 0으로 리셋하는 거죠?" → "네, 더 작아지면(음수) 0을 갖는 게 낫기 때문입니다.")

## 15. 정리: sublinear 결정적 알고리즘은 존재하지 않는다

**정리.** 최대 부분수열 합 문제를 sublinear 시간에 푸는 결정적(deterministic) 알고리즘은 존재하지 않는다. (증명 스케치로 제시 — "proof"가 아니라 "proof sketch"라고 명시.)

**증명 스케치.** 그런 알고리즘이 있다고 가정하자. 실행시간 $f(n)$이 $\Omega(n)$이 아니므로, 충분히 큰 어떤 $n_0$에 대해 입력 $a_1,\dots,a_{n_0}$이 존재해서 알고리즘이 수행하는 기본 연산 수가 $n_0$보다 엄격히 작다 — 즉 알고리즘이 **한 번도 들여다보지 않는 원소** $a_k$가 존재한다.

- **경우 1**: 모든 최대합 부분수열이 $a_k$를 포함한다면, $a_k$를 $-\infty$로 바꿔서 같은 입력으로 다시 돌린다고 하자. 알고리즘은 $a_k$에 접근하지 않으므로 출력이 그대로인데, 원래 최댓값을 주던 모든 부분수열의 합이 이제 $-\infty$가 되어 새 정답은 반드시 (변하지 않은) 알고리즘 출력보다 작아야 한다 — 오답.
- **경우 2**: 그렇지 않다면 $a_k$를 $+\infty$로 바꾼다. 새 정답은 $+\infty$여야 하는데 알고리즘은 여전히 유한한 값을 출력 — 오답.

어느 경우든 알고리즘이 접근하지 않는 값을 살짝 바꾸는 것만으로 정확성이 깨지므로, sublinear 알고리즘은 존재할 수 없다는 것이 직관이다.

## 16. 이 문제를 통해 본 강좌 전체 지도 + "효율적 알고리즘"의 정의

교수는 이 한 문제(최대 부분수열 합)를 통해 **이번 학기 전반부에서 다룰 알고리즘 설계 기법을 거의 다 미리 보여줬다**고 정리했다(딱 하나만 남았다고 언급했으나 그게 무엇인지는 이 시점에 밝히지 않음 — 추측하지 않는다). 전반부에서는 이 기법들을 다른 문제에 적용하는 예시를 계속 볼 것이라고 — "기법을 말로 설명할 수는 있지만 그것만으론 절대 배울 수 없다. 직접 여러 문제를 풀어보면서 익히게 된다."

**후반부 2대 주제**:
1. **Network flow** — 전반부의 문제들이 주로 설계 기법을 보여주기 위한 예시였다면, network flow는 컴퓨터과학 전반에 응용이 많은 "진짜로 풀고 싶은" 문제. 이 문제를 풀고 분석한 뒤, 다른 문제를 푸는 subroutine으로 어떻게 쓰이는지도 다룬다.
2. **NP-completeness** — 효율적 알고리즘의 존재 여부를 모르는(사실상 존재하지 않는다고 의심되는) 문제들을 식별·분류하는 수학적 틀.

**정의 1 (효율적 알고리즘).** 알고리즘의 실행시간이 입력 크기에 대한 다항식으로 bound되면 그 알고리즘은 **효율적**이라고 한다.

이 정의에 비추어 보면 최대 부분수열 합 문제는 "쉬운" 문제였다 — 가장 나이브한 첫 알고리즘(Alg 1/2)조차 $O(n^3)$으로 이미 다항식이었기 때문이다. 앞으로 다룰 다른 문제들 중에는 나이브한 알고리즘조차 지수 시간인 경우가 많을 것이라고 예고했다.

## 18. Closest Pair 문제 도입 (다음 시간에 계속)

전반부 첫 실제 문제로 **Closest Pair**를 도입했다.

**문제 정의.** 2차원 유클리드 평면 위의 점 $n$개가 주어졌을 때, 가장 가까운 점 쌍을 찾아라.

나이브하게 모든 쌍을 비교하면 $O(n^2)$로 자명하게 풀리므로, 목표는 이를 개선하는 것.

**특수 사례(1차원)로 먼저 접근.** 점들이 한 직선 위에 있는 경우를 먼저 생각해보자고 제안. 학생 답변: 가장 왼쪽 점부터 시작해서 인접한 다음 점까지의 거리를 차례로 계산하고 최솟값을 취하면 됨. 실행시간을 묻자 한 학생이 $O(n \log n)$이라고 답했고, 이유는 **정렬이 먼저 필요**하기 때문 — 입력은 임의 순서로 주어지므로("특정 순서를 가정할 수 있다면 애초에 첫 두 점이 가장 가깝다고 가정하지 않을 이유가 없다"), $x$좌표 기준 정렬 후에야 "가장 왼쪽"이 뭔지 알고리즘이 알 수 있다.

**스포일러 겸 다음 문제 제시.** 지금까지 배운 재귀 알고리즘은 merge sort와 최대 부분수열 합 알고리즘, 둘 다 입력을 절반으로 나누는 구조였다. 같은 질문을 1차원 Closest Pair에 다시 던졌다: **"재귀로 이 문제를 풀 수 있는가? 어떻게, 그리고 실행시간은?"** — 시간이 다 되어 **이 질문에 대한 답은 이 시점에 공개되지 않았고 다음 강의에서 이어가겠다고 명시**. (이 노트는 이 지점에서 추측하지 않는다 — `lec02.pdf`/`lec03.pdf`에 이후 강의로 보이는 정식 전개가 있지만, 실제로 강의에서 다뤄지기 전까지는 끌어오지 않았다.)

## Day 3 (2026-09-09) — Closest Pair: 2차원 분할정복 알고리즘 (`lec03.pdf`)

> 소스: `lec03.pdf`(2017년도 강의노트 원본, 4쪽 — 내용이 현재 강의와 일치함을 이미 확인). 지난 시간(merge sort 스켈레톤 재사용, $x$좌표 정렬 필요성)에서 바로 이어짐.

- **스켈레톤 재사용**: merge sort와 같은 구조로 입력을 절반으로 나눠 각 절반을 재귀적으로 풀고, 두 절반의 결과(각각의 "최근접 쌍")를 합치는 **merge 단계**가 문제라는 것부터 시작. 왼쪽 절반의 최근접 쌍, 오른쪽 절반의 최근접 쌍, 그리고 **한쪽엔 왼쪽 점, 다른 한쪽엔 오른쪽 점이 있는 쌍** 세 가지 후보(subsolution) 중 최솟값을 답으로 삼아야 하는데, 세 번째 경우가 나이브하게 하면 각 절반의 모든 점끼리 다 비교해야 해서($O(n^2)$) merge sort처럼 $O(n)$ merge가 안 되는 게 핵심 난관.
- **버전 1의 실패와 교훈**: 단순히 "경계선 근처의 점들만 보면 되지 않을까"는 아이디어를 시도했으나 반례(경계 근처가 아닌 먼 점들 사이에서 최근접 쌍이 나올 수 있음)로 기각. 하지만 이 시도가 완전히 무의미하진 않았다는 게 요지 — 그 실패가 진짜 조건이 뭔지 좁혀줬다는 취지의 코멘트.
- **핵심 개념 — $\delta$(델타)와 좁은 띠(narrow band/strip)**: $\delta$를 왼쪽/오른쪽 절반 각각의 재귀 호출이 반환한 최근접 거리 중 **더 작은 값**으로 정의. 그러면 "한쪽엔 왼쪽 점, 다른 한쪽엔 오른쪽 점이 있는" 진짜 최근접 쌍이 존재한다면, 그 두 점은 반드시 경계선(중앙 $x$좌표, $x^*$)으로부터 각각 $\delta$ 이내, 즉 폭 $2\delta$인 좁은 띠 안에 있어야 한다는 것을 증명 — 그렇지 않은 점(그 점이 어느 쪽에 짝지어지든 이미 $\delta$보다 가까운 같은 쪽 점이 있는 경우)은 최종 답의 후보가 될 수 없기 때문.
- **1차원 유추와 그 실패, 그리고 "매직 넘버 11"**: "이 띠 안의 점들만 $x$좌표로 정렬해서 인접한 것끼리만 비교하면 되지 않는가"(1차원 Closest Pair와 유사한 접근)를 시도했지만, 2차원에서는 $x$좌표가 비슷해도 $y$좌표가 멀 수 있어서 실패(반례로 시연). 대신 **좁은 띠 안의 점을 $y$좌표로 정렬**하고, 한 점에서 $y$좌표 기준으로 **가까운 11개의 점**까지만 비교하면 충분하다는 것을 기하학적 논증(한 변의 길이가 $\delta$인 정사각형 안에는 $\delta$ 이상 떨어진 점이 최대 4개까지만 들어갈 수 있다는 원 채우기(circle-packing) 논증, 즉 세로로 $\delta/2 \times \delta/2$ 칸을 나눠 비둘기집 원리 적용)으로 증명. 학생들의 여러 질문(왜 정확히 11인지, $x$좌표가 아니라 $y$좌표로 정렬하는 이유 등)에 답하며 이 부분을 상당히 길게 다룸.
- **최종 알고리즘**: (1) 전체 점을 $x$좌표 기준 정렬한 리스트 $P$와 $y$좌표 기준 정렬한 리스트를 준비, (2) $P$를 절반으로 나눠 재귀 호출 → 왼쪽 최근접 쌍 $(p_{l1}, p_{l2})$, 오른쪽 최근접 쌍 $(p_{r1}, p_{r2})$, (3) $\delta = \min(\text{왼쪽 거리}, \text{오른쪽 거리})$, (4) 경계 $x^*$ 기준 폭 $2\delta$ 띠 안의 점들을 뽑아 $y$좌표로 정렬한 리스트 $S_y$ 구성, (5) $S_y$를 훑으며 각 점을 그다음 최대 11개 이웃과만 비교해 최근접 쌍 후보 $(p_{m1}, p_{m2})$ 계산, (6) 세 후보 $(p_{l1},p_{l2})$, $(p_{r1},p_{r2})$, $(p_{m1},p_{m2})$ 중 거리가 가장 짧은 쌍을 반환.
- **정확성의 미묘한 지점**: $(p_{m1}, p_{m2})$가 **실제 전역 최근접 쌍과 일치할 필요는 없다** — 그저 "만약 진짜 답이 띠를 가로지르는 쌍이라면, 이 방법이 그걸 찾아낸다"는 것만 보장하면 충분하다는 점을 강조(이미 왼쪽/오른쪽 재귀가 각자 영역 안의 최근접 쌍은 처리했으므로).
- **실행시간 분석**: merge 단계 자체(띠 추출 + 11개 이웃 비교)는 $O(n)$으로 merge sort의 merge 단계와 구조적으로 동일. 다만 **$S_y$를 만들기 위한 정렬이 추가로 필요**하다는 점이 merge sort와 다르고, 이 정렬 비용 때문에 전체 실행시간이 merge sort보다 "약간 더 나쁘다"(정확한 점화식과 최종 복잡도는 강의에서 시간이 부족해 다음 시간으로 이월 — 이 노트는 추측하지 않는다).
- 강의는 다음 시간에 나눠줄 핸드아웃 예고와 함께 마무리.

## Day 4 (2026-09-11) — Master Theorem, Closest Pair 마무리, Integer Multiplication 도입

> 소스: 강의 녹음 STT 전사(`2026-09-11-algorithm-analysis-1`, whisper-1 verbose_json 기반 재전사 → 문단화·한영 대역, `_private/2026-2/algorithm-analysis/week-01/`에 원본 보관). Master theorem 부분은 지난 시간 배포된 요약 핸드아웃을 칠판에서 재구술한 것(핸드아웃 원본 파일 자체는 이 레포에 없음). Closest Pair 부분은 Day 3(`lec03.pdf`)의 cliffhanger("정확한 점화식과 최종 복잡도는 다음 시간으로 이월")에서 바로 이어진다. **Integer Multiplication 부분은 이번 학기에 대응하는 슬라이드·핸드아웃이 전혀 없다 — 전적으로 강의 녹음에서 실제로 언급된 내용만 기록했고, 표준적인 정수 곱셈 알고리즘 설명(예: 자릿수 기반 개선 곱셈법 등)은 교수가 아직 다루지 않았으므로 이 노트에서도 끌어오지 않았다.**

### A. Master Theorem (지난 시간 핸드아웃 요약, 칠판 재구술)

**정리 (Master Theorem).** $a \ge 1$, $b > 1$이 상수이고 $f(n) \ge 0$일 때, 음이 아닌 정수 위에서 점화식
$$T(n) = aT(n/b) + f(n)$$
으로 정의되는 함수 $T(n)$을 생각하자(기저 사례는 어떻게든 주어져 있다고 가정한다). 세 가지 경우는 다음과 같다.

1. 어떤 상수 $\epsilon>0$에 대해 $f(n) = O(n^{\log_b a - \epsilon})$이면, $T(n) = \Theta(n^{\log_b a})$.
2. 어떤 상수 $k \ge 0$에 대해 $f(n) = \Theta(n^{\log_b a}\log^k n)$이면, $T(n) = \Theta(n^{\log_b a}\log^{k+1} n)$.
3. 어떤 상수 $\epsilon>0$에 대해 $f(n) = \Omega(n^{\log_b a + \epsilon})$이고, 어떤 상수 $c<1$이 존재해 충분히 큰 모든 $n$에 대해 $a\cdot f(n/b) \le c\cdot f(n)$(**정규성 조건**, regularity condition)이면, $T(n) = \Theta(f(n))$.

**해석·적용상 주의점 (교수가 직접 짚은 것).**
- $T(n)$은 음이 아닌 정수에서만 정의되므로 $n/b$가 정수가 아닐 수 있는데, 이때 $n/b$는 **ceiling이든 floor이든 원하는 쪽으로 자유롭게 해석**해도 된다 — 그 해석 하에 점화식이 정리가 요구하는 형태로 성립하기만 하면 정리를 적용할 수 있다.
- **이 정리는 모든 점화식을 포괄하지 않는다.** 부분문제 크기가 $n/b$ 꼴이 아닌 경우(예: $T(n-1)$, $T(\sqrt n)$)는 애초에 적용 대상이 아니다. 형태는 맞아도 $f(n)$이 세 경우 중 어디에도 안 들어맞을 수 있다 — 강의에서 든 예시: $\log_b a = 2$일 때 $f(n)=n^2$는 $k=0$으로 두면 경우 2($n^{\log_b a}\log^k n = n^2\log^0 n$)에 정확히 들어맞지만, $f(n) = n^2/\log n$은 경우 2가 요구하는 $k=-1$이 허용되지 않아 안 맞고, 경우 1도 안 맞으며($\epsilon>0$인 한 $n^{\log_b a-\epsilon}$은 $n^2/\log n$보다 항상 엄격히 느리게 자라서 $f(n)$이 그 $O$가 될 수 없음), 경우 3도 안 맞는다($f(n)$이 $n^{\log_b a}$보다 다항식 차수만큼 더 빨리 자라야 하는데 $n^2/\log n$은 그렇지 않음). 이런 $f(n)$에 대해서는 마스터 정리가 답을 주지 못한다.
- 경우 3의 정규성 조건은 **충분히 큰 $n$에 대해서만** 성립하면 되고(예: $n\ge10^6$부터만 성립해도 무방), 실무적으로는 $f(n) = \Omega(n^{\log_b a+\epsilon})$ 조건만 만족하면 정규성 조건도 거의 자동으로 따라온다 — 병적인(pathological) 함수에만 실제로 문제가 된다.

### B. Closest Pair 실행시간 (1차): Master Theorem 적용 → $O(n\log^2 n)$

Day 3 알고리즘(이하 **Algorithm 1**)을 그대로 다시 쓰고 시간복잡도를 형식화한다. $T(n)$을 입력이 $n$개 점일 때 재귀 함수가 수행하는 최악의 경우 기본 연산 수라 하자.

- **기저 사례** ($n\le3$): 세 점 이하이면 가능한 쌍을 전부 나열해 비교한다. 정확한 연산 수는 점의 좌표에 따라 달라지지만(예: 10, 11, 12 등), 항상 그 값 이상인 어떤 상수 $C_1$이 존재한다 — $T(n) \le C_1$.
- **재귀 사례** ($n\ge4$): $L_x$는 $\lfloor n/2\rfloor$개, $R_x$는 $\lceil n/2\rceil$개 점을 가지므로 두 재귀 호출 비용은 $T(\lfloor n/2\rfloor)+T(\lceil n/2\rceil)$인데, 마스터 정리는 floor/ceiling을 구분할 필요가 없으므로 그냥 $2T(n/2)$로 쓴다. 나머지 부분(경계 판정, $\delta$ 계산, 좁은 띠 $S$ 추출, $S_y$를 얻기 위한 **정렬**, 11개 이웃 비교)은 Day 3에서 이미 짚었듯 $S_y$ 정렬 단계가 지배하며 이는 $O(n\log n)$이다 — 어떤 상수 $C_2>0$에 대해 $C_2\cdot n\log n$으로 안전하게 위로 유계.

$$T(n) \le 2T(n/2) + C_2\, n\log n \qquad (n\ge4)$$

이건 **부등식**이라 마스터 정리를 바로 쓸 수 없다. 그래서 보조함수 $T'(n)$을 $T'(n)=C_1$ ($n\le3$), $T'(n)=2T'(n/2)+C_2\, n\log n$ ($n\ge4$)로 **등식**으로 정의하면, 귀납법으로 모든 $n$에 대해 $T(n)\le T'(n)$임을 쉽게 보일 수 있다(기저는 자명, 귀납 단계는 $T(n)\le 2T(n/2)+C_2 n\log n \le 2T'(n/2)+C_2 n\log n = T'(n)$). $T'(n)$은 등식을 만족하므로 마스터 정리를 바로 적용할 수 있다: $a=2,b=2 \Rightarrow \log_b a=1$이고 $f(n)=C_2\,n\log n=\Theta(n^1\log^1 n)$이므로 경우 2($k=1$)에 해당해

$$T'(n)=\Theta(n\log^2 n).$$

따라서 $T(n)\le T'(n)=\Theta(n\log^2 n)$, 즉 $T(n)=O(n\log^2 n)$이다 — 단 **이건 $T$ 자체의 $\Theta$가 아니라 상한일 뿐**이다(정확히 $\Theta(n\log^2 n)$임이 증명된 건 보조함수 $T'$뿐). 여기에 전처리($x$-정렬, $O(n\log n)$)를 더해도 전체 실행시간은 $O(n\log^2 n)$.

### C. "5분간 거짓말" — 흔한 함정 하나, 그리고 실제 개선 $O(n\log n)$

교수가 미리 예고하고 시연한 **의도된 오류**("학생들이 실제로 자주 저지르는 실수를 보여주기 위해 5분간 거짓말을 하겠다"): 전처리에서 $y$좌표 정렬 전체 리스트 $P_y$를 한 번 더 만들어두고(비용 $\Theta(n\log n)$, 어차피 1회성 전처리이므로 무방), 매 재귀 호출마다 $S_y$가 필요할 때 이 $P_y$ **하나를 처음부터 끝까지** 스캔해 "이 점이 좁은 띠 $S$에 속하는가"만 판정하고 속하면 새 리스트 끝에 복사한다고 하자. 스캔 1회는 $O(n)$(점마다 상수 시간)이므로 $S_y$ 준비 비용을 $\Theta(n\log n)$에서 $\Theta(n)$으로 줄일 수 있고, 그러면 마스터 정리 경우 2에서 $k=0$이 되어 $T(n)=\Theta(n\log n)$을 얻는다는 주장.

**거짓말이 숨은 지점.** 이 논증은 "$n$"으로 서로 다른 두 가지를 가리키고 있었다 — 하나는 점화식의 진짜 $n$(그 재귀 호출 자신이 받은 부분문제의 점 개수), 다른 하나는 (틀린 버전에서 스캔 대상으로 쓴) **원래 입력 전체의** 점 개수. 재귀 호출이 아무리 작은 부분문제를 다루더라도 매번 원래 입력 전체 크기에 비례하는 $P_y$를 훑고 있으므로, 각 호출의 실제 비용은 자신의 부분문제 크기가 아니라 원래 입력 크기에 비례한다. 그런데 알고리즘 전체에서 만들어지는 재귀 호출의 총 개수 자체가 원래 입력 크기에 비례하므로, 총 비용은 (호출 수) $\times$ (호출당 비용) $\sim$ 이차 시간이 되어버려 개선이 아니다. 교수의 코멘트: "많은 학생이 실제로 이 실수를 저지른다" — 원래 입력 크기와 재귀 호출 시점의 부분문제 크기를 똑같이 $n$이라고 부르는 데서 오는 흔한 함정.

**실제로 유효한 개선.** 실패한 시도에서 건질 수 있는 진짜 아이디어는 맞다: "이미 정렬돼 있고 내가 관심 있는 점을 전부 포함하는 리스트가 있다면, **그 리스트 자체의 길이에 비례하는** 선형 시간 스캔만으로 정렬된 부분 리스트를 뽑아낼 수 있다." 문제는 매번 "원래 입력 전체"를 훑었다는 것뿐이었으므로:

- 각 재귀 호출에 $P_x$($x$-정렬, Day 3와 동일)뿐 아니라, **그 호출이 다루는 점들과 정확히 같은 집합을 $y$좌표로 정렬한 $P_y$**도 함께 넘긴다(불변식: 어떤 재귀 호출에 주어지는 $P_x$와 $P_y$는 항상 같은 점 집합).
- 최초 호출에는 전처리에서 만든 전체 $y$-정렬 리스트를 그대로 넘긴다(1회성 $\Theta(n\log n)$).
- 호출 안에서 $P_x$를 인덱스로 잘라 $L_x, R_x$를 만든 뒤, **그 호출 자신의 $P_y$**를 한 번 스캔하며 각 점이 $L_x$ 쪽인지 $R_x$ 쪽인지 판정해 $L_y$ 또는 $R_y$ 끝에 복사한다 — 이 스캔은 그 호출 자신의 부분문제 크기에 비례하므로 진짜 $O(n)$($n$이 이제 정확히 점화식의 $n$).
- 좁은 띠 $S_y$도 같은 방식으로 그 호출의 $P_y$를 한 번 스캔해서 만든다 — **정렬이 전혀 필요 없다.**

이렇게 하면 호출 하나당 추가 작업(경계 계산 + $L_y/R_y/S_y$ 준비 + 11개 이웃 비교)이 전부 $\Theta(n)$이 되어

$$T(n) = 2T(n/2) + \Theta(n)$$

를 얻는다. 마스터 정리 경우 2($a=2,b=2\Rightarrow\log_b a=1$, $k=0$)에 의해 $T(n)=\Theta(n\log n)$이고, 전처리($x$-정렬 + $y$-정렬, 둘 다 $\Theta(n\log n)$)를 더해도 **전체 실행시간은 $O(n\log n)$** — 애초 목표였던 시간복잡도 달성.

**대안: bottom-up 구현도 가능.** 위 방식은 top-down(맨 처음 전체 $y$-정렬 리스트를 준비해 아래로 쪼개어 넘긴다)이다. 반대로 재귀 함수가 "답"과 더불어 **자기 부분집합을 $y$좌표로 정렬한 리스트**도 함께 반환하도록 만들고, 상위 호출은 두 자식 호출이 돌려준 $L_y, R_y$를 **merge sort의 merge 단계처럼 병합**해서 자신의 $P_y$를 상향식으로 조립해도 된다(기저 사례는 3개 이하 점을 직접 $y$-정렬해 반환). 두 방식 모두 $O(n\log n)$.

**남은 코멘트 두 가지 (교수).** (1) 11은 유효한 값일 뿐 유일하거나 최적인 값은 아니다 — 더 세심한 분석으로 줄일 수 있으나 강의에서 다루지는 않았다. (2) 이 예제로 처음 이름 붙인 방법론: **분할정복(divide-and-conquer)** — 대체로 비슷한 크기의 부분문제로 나누고(여기서는 $L_x,R_x$가 최대 1개 차이), 재귀로 각각 풀고, 대개 가장 창의력이 필요한 부분은 그 해들을 합쳐 큰 문제의 해로 만드는 **merge 단계**라는 것. 재귀 알고리즘이므로 실행시간 분석에는 항상 마스터 정리가 유용하다. (지금까지 본 분할정복 예시로 최대 부분수열 합의 $O(n\log n)$ 버전과 closest pair를 언급.)

### D. Closest Pair 정확성의 formal proof (Lemma 1, Lemma 2, 강한 귀납법)

**Lemma 1.** $p_i$가 왼쪽 절반, $p_j$가 오른쪽 절반에서 온 점이고 $\mathrm{dist}(p_i,p_j) < \delta$이면, $x_i, x_j \in (x^*-\delta,\ x^*+\delta)$이다(즉 둘 다 좁은 띠 $S$ 안에 있다).

*Proof.* $p_i$가 왼쪽, $p_j$가 오른쪽에서 왔고 $x^*$가 경계이므로 $x_i \le x^* \le x_j$. 따라서 $x^*-x_i \le x_j-x_i$이고, $x_j-x_i$(음이 아님)는 $\mathrm{dist}(p_i,p_j)$ 이하이며 이는 가정에 의해 $\delta$보다 작다. 즉 $x^*-x_i < \delta$, 다시 말해 $x_i > x^*-\delta$. $x_i \le x^*$와 합쳐 $x_i \in (x^*-\delta,\, x^*]$. 대칭적으로 $x_j \in [x^*,\, x^*+\delta)$. $\blacksquare$

**Lemma 2.** $p,q \in S$(좁은 띠)이고 $\mathrm{dist}(p,q)<\delta$이면, $S_y$($y$좌표 정렬 리스트)에서 $p,q$는 서로 11자리 이내에 있다.

*Proof.* 폭 $2\delta$인 좁은 띠를 한 변 길이 $\delta/2$인 정사각형("박스")으로 완전히 타일링한다 — 폭이 $2\delta$이므로 가로 방향 한 "행(row)"은 $2\delta/(\delta/2)=4$개의 박스로 이루어진다. 경계($x=x^*$)에 걸친 점은 자신이 속한 절반 쪽 박스에 임의로(그러나 일관되게) 배정한다.

*각 박스는 $S$의 점을 최대 1개만 포함한다.* 한 박스 안 임의의 두 점 사이 거리는 최대 대각선 길이 $(\delta/2)\sqrt2=\delta/\sqrt2 <\delta$이다. 그런데 $\delta$는 두 재귀 호출이 반환한 최근접 거리의 최솟값이므로, **같은 절반 안의 어떤 두 점도 거리가 $\delta$ 미만일 수 없다.** 위의 경계 처리 규칙에 의해 각 박스는 완전히 한쪽 절반에만 속하므로, 한 박스 안의 점들은 모두 같은 절반 출신이어야 한다 — 그런데 같은 절반 두 점의 거리는 $\delta$ 이상이어야 하고 박스 내부 최대 거리는 $\delta$ 미만이므로, 한 박스에 점이 2개 이상 있을 수 없다.

*귀류법.* $p,q\in S_y$에서 $\mathrm{dist}(p,q)<\delta$이지만 $S_y$ 순서상 서로 12자리 이상 떨어져 있다고 가정하자(일반성을 잃지 않고 $p$가 $q$보다 앞선다고 하자). $S_y$에서 $p$부터 $q$까지(양 끝 포함) 점은 최소 13개이고, 이들의 $y$좌표는 전부 $[y_p,y_q]$ 안에 있다. $p$가 속한 박스의 행과 $q$가 속한 박스의 행 사이에 행이 최대 1개뿐이라고 하면, ($p$의 행, 사이 행 최대 1개, $q$의 행을 합쳐) 최대 3개 행 $=$ 최대 $3\times4=12$개 박스에 이 13개 점이 전부 들어가야 한다 — 비둘기집 원리에 의해 어떤 박스가 점을 2개 받아야 하는데, 이는 앞서 보인 "박스당 최대 1점"과 모순이다. 따라서 $p$의 행과 $q$의 행 사이에는 **적어도 2개의 행**이 있어야 한다. 한 행의 높이가 $\delta/2$이므로, 그 사이에 완전한 행 2개가 있다는 것은 (최악의 경우를 따져도) $y_q-y_p \ge 2\times(\delta/2)=\delta$를 뜻한다. 그런데 $\mathrm{dist}(p,q)\ge |y_q-y_p|$이므로 $\mathrm{dist}(p,q)\ge\delta$가 되어 가정 $\mathrm{dist}(p,q)<\delta$와 모순이다. $\blacksquare$

**정리 (Algorithm 1의 정확성).** Day 3~4에서 완성한 재귀 알고리즘(§C의 선형시간 병합 포함)은 항상 최근접 쌍을 올바르게 반환한다.

*Proof (입력 점 개수에 대한 강한 귀납법).* **기저 사례** ($n\le3$): 모든 쌍을 나열하므로 자명. **귀납 단계** ($n\ge4$): 강한 귀납 가정에 의해 $(p_{l1},p_{l2})$는 $L_x$의 최근접 쌍, $(p_{r1},p_{r2})$는 $R_x$의 최근접 쌍이다($|L_x|,|R_x|<|P_x|$이므로 강한 귀납법이 필요). $(p^*_1,p^*_2)$를 전체 $P_x$의 (하나의) 최근접 쌍이라 하고 $\delta=\min(\mathrm{dist}(p_{l1},p_{l2}),\ \mathrm{dist}(p_{r1},p_{r2}))$라 하자. $\delta$는 어떤 특정한 쌍의 거리이므로 전체 최솟값 $\mathrm{dist}(p^*_1,p^*_2)$ 이상이다.

- **경우 1 ($\delta > \mathrm{dist}(p^*_1,p^*_2)$).** $(p^*_1,p^*_2)$가 왼쪽 절반 안에만 있다면 귀납 가정에 의해 $\mathrm{dist}(p_{l1},p_{l2}) \le \mathrm{dist}(p^*_1,p^*_2) < \delta \le \mathrm{dist}(p_{l1},p_{l2})$가 되어 모순(오른쪽도 대칭). 따라서 $(p^*_1,p^*_2)$는 반드시 한쪽에 하나씩 있는 **경계를 가로지르는 쌍**이다. Lemma 1에 의해 둘 다 $S$ 안에 있고, Lemma 2에 의해 $S_y$에서 서로 11자리 이내다 — 그러므로 알고리즘이 $S_y$를 훑으며 각 점을 다음 11개와 비교할 때 이 쌍이 반드시 검토되어, 알고리즘이 찾는 세 번째 후보 $(p_{m1},p_{m2})$의 거리는 $\mathrm{dist}(p^*_1,p^*_2)$ 이하가 된다. 그런데 $(p^*_1,p^*_2)$가 전체 최솟값이므로 그보다 작을 수는 없다 — 즉 정확히 같다. 세 후보 $(p_{l1},p_{l2}),(p_{r1},p_{r2}),(p_{m1},p_{m2})$ 중 최솟값을 반환하므로 알고리즘은 전체 최근접 거리와 같은 거리를 갖는 쌍을 반환한다.
- **경우 2 ($\delta = \mathrm{dist}(p^*_1,p^*_2)$).** 이미 두 재귀 호출 중 하나가 전체 최적값을 달성한 상태다. $S_y$ 스캔에서 나온 세 번째 후보 $(p_{m1},p_{m2})$는 (정의되어 있다면) 입력에 실제로 존재하는 서로 다른 두 점의 쌍일 뿐이므로, 그 거리는 전체 최솟값인 $\delta$보다 작을 수 없다. 따라서 세 후보 중 최솟값은 여전히 $\delta$이고, 이는 전체 최적값과 같다.

두 경우 모두 알고리즘이 반환하는 거리가 전체 최근접 거리와 일치하므로 귀납이 완성된다. $\blacksquare$

**정리(요약).** Closest Pair는 §C의 선형시간 병합 버전 기준 $O(n\log n)$ 시간에, §B의 (정렬 기반) 단순 버전 기준 $O(n\log^2 n)$ 시간에 정확하게 풀린다.

### E. Integer Multiplication 도입 (⚠️ 이 학기용 슬라이드/핸드아웃 없음 — 강의 녹음 기준으로만 기록)

**문제 도입 배경.** 덧셈·뺄셈·곱셈·나눗셈을 상수 시간 연산으로 취급하는 것은 RAM(random access machine) 모델의 가정이다 — 고정 워드 크기(예: 64비트) 프로세서에서 네이티브 산술 명령이 상수 시간에 답을 주고, 임의 메모리 주소도 상수 시간에 접근·대입·비교된다는 점에서 실제 하드웨어에 대한 좋은 근사다. 그런데 워드 크기를 넘는 매우 큰 정수(강의 예시: $64k$비트 정수끼리의 곱)를 다뤄야 하는 응용에서는, 고정 크기 산술 명령만으로 훨씬 큰 정수의 곱셈을 **구현**해야 하므로 RAM 모델이 더는 유효한 근사가 아니다 — 그래서 정수 곱셈 자체를 상수 시간이 아니라 **분석 대상 알고리즘**으로 다루기 시작한다.

**문제 정의.** 양의 정수 $p, q$가 주어지면 $p\cdot q$를 계산하라.

**제시된 나이브 알고리즘** (덧셈만으로 곱셈을 구현하는 방식):
```
ans ← 0
for i ← 1, …, p do
    for a ← 1, …, q do
        ans ← ans + 1
return ans
```
정확성은 자명하다(단위 증가를 $p\times q$번 반복해 $p\cdot q$를 얻음). 실행시간은 $\Theta(p\cdot q)$ — 교수는 편의상 이를 $O(p,q)$로 표기했다(두 인자 각각에 대한 바운드라는 뜻). **교수 본인이 강의 중 "이 실행시간 근사치 자체에도 이의가 있지만 지금은 얘기하지 않겠다"고 명시적으로 유보** — 무엇에 대한 이의인지는 이 시점에 밝혀지지 않았다(이 노트는 추측하지 않는다).

**효율성 질문과 열린 cliffhanger.** Day 2 §16의 "효율적 알고리즘" 정의(실행시간이 입력 크기의 다항식으로 bound)를 그대로 적용하면, $O(p,q)$는 $p,q$에 대한 다항식이므로 언뜻 효율적으로 보인다. 학생 여론조사에서 상당수가 "효율적이지 않다"에 손을 들었고, 교수는 **"우리 정의를 따르더라도 답은 '아니오', 이 알고리즘은 효율적이지 않다"**고 명시적으로 확인했다 — 그러나 **그 이유는 다음 강의로 명시적으로 이월되었다.** (이 노트는 이 지점에서 추측하지 않는다 — "다항식으로 보이는 바운드가 왜 실은 비효율적인가"에 대한 표준적 설명(예: 입력 크기를 값 자체가 아니라 자릿수로 재는 관점)은 실제로 강의에서 다뤄지기 전까지 끌어오지 않는다.)

**참고 (교수 예고).** Integer Multiplication도 지금까지 본 예시(최대 부분수열 합의 $O(n\log n)$ 버전, closest pair)와 마찬가지로 **분할정복** 방법론으로 다룰 것이라고 명시적으로 예고하고 강의를 마쳤다 — 구체적인 분할정복 알고리즘은 아직 제시되지 않았다.

## Day 5 (2026-09-16) — Integer Multiplication의 효율성 규명과 분할정복 (4-way → 3-way), 새 문제 예고

> 소스: 강의 녹음 STT 전사(`2026-09-16-algorithm-analysis-1`, en/ko 대역, `_private/2026-2/algorithm-analysis/week-01/`에 원본 보관). Day 4 §E의 cliffhanger("$O(p,q)$가 왜 비효율적인지"와 "실행시간 표기 자체에 대한 이의")에서 바로 이어진다. **⚠️ 이 학기용 슬라이드/핸드아웃 없음 — Day 4 §E와 마찬가지로 이 섹션 전체가 강의 녹음에서 실제로 언급된 내용만으로 구성되어 있다.**

### A. Day 4의 cliffhanger 해소 — 왜 나이브 $O(p,q)$ 알고리즘은 비효율적인가

**입력 크기를 값이 아니라 비트 수로 재야 한다.** 교수는 먼저 지난 시간 학생이 이 알고리즘의 실행시간을 $O(p^3)$이라 답했던 것을 상기시키며 "정확하진 않지만 우리 목적엔 충분히 괜찮은 답"이라 평가했던 것을 되짚었다. 그다음 Day 2 §16의 "효율적 알고리즘 = 실행시간이 입력 크기의 다항식" 정의를 다시 적용했다: $\Theta(p\cdot q)$(교수 표기 $O(p,q)$)는 $p,q$ 자체에 대해서는 다항식이지만, **입력 크기는 $p,q$라는 값이 아니라 그 값을 나타내는 데 필요한 비트(기호) 수**다. 이는 RAM 모델을 더 이상 쓸 수 없어서만이 아니라, RAM 모델 하에서도 "입력 크기"의 정의 자체가 원래 "주어진 입력을 표현하는 데 필요한 기호 개수"이기 때문이라고 명시적으로 짚었다.

$p,q$를 표현하는 데 필요한 비트 수는 대략
$$n \approx \log_2 p + \log_2 q,$$
즉 $p,q$는 대략 입력 크기 $n$에 대해 $2^{\Theta(n)}$ 꼴이다. 따라서 $\Theta(p\cdot q)$는 입력 크기 $n$ 기준으로 **지수 시간**이다 — "우리 자신의 정의 하에서도" 이 알고리즘은 비효율적이라고 Day 4 말미에 확인했던 것의 이유가 바로 이것이다. (교수: "이제 우리 목표는 먼저 효율적인 알고리즘을 만들고, 그다음 실행시간을 더 개선하는 것.")

**표기 $O(p,q)$/$O(p^3)$ 자체에 대한 이의의 정체.** Day 4에서 유보됐던 "이 실행시간 근사치 자체에 대한 이의"도 이 자리에서 풀렸다: `ans ← ans + 1`의 각 덧셈은 상수 시간이 아니다 — `ans`는 최대 $p\cdot q$까지 커질 수 있는 매우 긴 정수이므로, 이진수로 1을 더하는 데 걸리는 시간은 그 정수의 길이, 즉 대략 $\log_2 p + \log_2 q$에 비례한다. 따라서 더 정확한 실행시간은
$$\Theta\big(p\cdot q\cdot(\log_2 p + \log_2 q)\big)$$
꼴이 되어야 한다. 다만 이 보정 인수를 곱해도 "지수 시간"이라는 결론 자체는 바뀌지 않으므로, 교수는 "그래서 그 부분은 크게 신경 쓰지 않았다"고 밝혔다.

### B. 문제를 $n$비트 정수로 재정의, 초등학교식(그래드스쿨) 알고리즘 복습 — $\Theta(n^2)$

설명을 간단히 하기 위해 문제를 다음과 같이 재정의한다: $p,q$의 길이가 같다고 가정하고, 그 공통 길이를 $n$비트라 하자. 즉 **$n$비트 정수 $x,y$가 주어졌을 때 $x\cdot y$를 계산하라.**

이미 알고 있는 효율적인 알고리즘: 초등학교에서 배운 필산 곱셈(그래드스쿨 알고리즘)을 이진수로 그대로 옮긴 것 — $y$의 각 비트가 1이면 $x$를 해당 자리만큼 시프트해서 복사하고 0이면 건너뛴 뒤, 그렇게 만든 최대 $n$개의 행을 모두 더한다. 각 정수가 $n$비트이므로 최악의 경우 이 $n$비트를 $n$번 복사하고, 그 결과를 더하는 데는 적어놓은 행의 개수에 비례하는 시간이 걸려 전체 실행시간은 $\Theta(n^2)$이다. $n$이 입력 크기(의 절반)이므로 이는 **다항 시간, 즉 이미 효율적인 알고리즘**이다. 그러나 교수는 이보다 더 개선된 실행시간을 보여주겠다고 예고했다.

### C. 첫 번째 분할정복 시도 — 4개의 재귀 곱셈으로 나누기 (개선 없음, $\Theta(n^2)$)

**분할 방식.** $x$를 상위/하위 $n/2$비트로 나눠 $x = x_1\cdot 2^{n/2} + x_0$, 마찬가지로 $y = y_1\cdot2^{n/2}+y_0$이라 하자. 그러면
$$xy = x_1y_1\cdot2^{2\lfloor n/2\rfloor} + (x_1y_0+x_0y_1)\cdot2^{\lfloor n/2\rfloor} + x_0y_0$$
이고, 우변에 등장하는 $x_1y_1, x_1y_0, x_0y_1, x_0y_0$은 모두 더 작은 정수끼리의 곱이므로 재귀로 풀 수 있다.

**알고리즘** (이 노트에서 편의상 **Algorithm 2**라 부른다 — 교수는 이후 3-way 버전만 명시적으로 "Algorithm 3"이라 이름 붙였고 이 4-way 버전 자체엔 이름을 붙이지 않았지만, 그 번호가 자연스러운 다음 순번임을 시사한다):
```
function multiply(x, y, n):
    if n ≤ 3:
        return ElementaryMultiply(x, y)      # base case: use the elementary algorithm
    split x into x1, x0 and y into y1, y0    # upper/lower n/2 bits
    p1 ← multiply(x1, y1, ⌈n/2⌉)
    p2 ← multiply(x1, y0, ⌈n/2⌉)
    p3 ← multiply(x0, y1, ⌈n/2⌉)
    p4 ← multiply(x0, y0, ⌈n/2⌉)
    return p1·2^n + (p2+p3)·2^(n/2) + p4
```
(최종 반환식에서는 편의상 $2^{2\lfloor n/2\rfloor}$, $2^{\lfloor n/2\rfloor}$ 대신 $2^n$, $2^{n/2}$로 단순화해서 적었다 — 교수의 칠판 표기를 그대로 따름.)

**정확성 (귀납법, $n$에 대해).** $n\le3$이면 기저 사례라 자명. $n\ge4$이면 $x,y$를 둘로 나눈 각 조각은 $n$보다 엄격히 적은 비트를 가지므로 귀납 가정에 의해 네 재귀 호출 모두 올바른 곱을 반환하고, 위 대수적 항등식에 의해 반환값이 $xy$와 같다. (교수는 이 증명을 전부 칠판에 쓰지는 않고 "귀납법으로 보일 수 있다"는 선에서 넘어갔다.)

**실행시간.** 분할(배열 인덱싱)은 상수 시간, 결합 단계(시프트 + 덧셈, 길이 약 $2n$인 수들을 다룸)는 선형 시간이므로
$$T(n) = 4T(n/2) + \Theta(n).$$
마스터 정리 적용: $a=4, b=2 \Rightarrow \log_b a = \log_2 4 = 2$. $f(n)=\Theta(n) = O(n^{\log_b a - 1})$이므로 $\epsilon=1$로 두면 경우 1에 해당해
$$T(n) = \Theta(n^{\log_b a}) = \Theta(n^2).$$
즉 **4개의 재귀 호출로 나누는 이 시도는 그래드스쿨 알고리즘(§B)보다 전혀 개선되지 않는다** — 문제는 $\log_b a = 2$, 즉 재귀 호출이 4개라는 점이다. (교수는 이 알고리즘의 기저 사례를 왜 $n\le3$으로 정했는지 이 시점엔 "이유가 있었는데 기억이 안 난다"고 솔직히 인정했고, 그 이유는 §D에서 Algorithm 3의 증명 중에 다시 등장한다.)

### D. 개선된 시도 — 3개의 재귀 곱셈으로 줄이기 (Algorithm 3)

**핵심 관찰.** §C의 식에서 $x_1y_0$과 $x_0y_1$을 **각각** 알 필요는 없고, 그 **합**만 알면 된다. 그런데
$$x_1y_0 + x_0y_1 = (x_1+x_0)(y_1+y_0) - x_1y_1 - x_0y_0$$
이고, 우변의 $x_1y_1$과 $x_0y_0$은 (가운데 항을 구하려는 목적과 무관하게) 어차피 계산해야 하는 값이다. 따라서 곱을 2개 대신 1개, 즉 $(x_1+x_0)(y_1+y_0)$만 추가로 계산하면 가운데 항을 복원할 수 있다 — 재귀 호출이 4개에서 3개로 줄어든다.

**Algorithm 3:**
```
function multiply(x, y, n):
    if n ≤ 3:
        return ElementaryMultiply(x, y)
    split x into x1, x0 and y into y1, y0
    p1 ← multiply(x1+x0, y1+y0, ...)   # recursive call on (x1+x0), (y1+y0)
    p2 ← multiply(x1, y1, ⌈n/2⌉)
    p3 ← multiply(x0, y0, ⌈n/2⌉)
    return p2·2^n + (p1 - p2 - p3)·2^(n/2) + p3
```
$p_1-p_2-p_3$은 정의상 $x_1y_0+x_0y_1$과 같고 이는 두 음이 아닌 곱의 합이므로 **항상 음이 아니다** — 계산 중 음수 처리를 걱정할 필요가 없다는 점을 교수가 짚었다. 결합 단계는 이전과 마찬가지로 뺄셈 하나가 추가된 것 말고는 동일하므로 여전히 선형 시간이다.

**정확성 증명 (Algorithm 3, $n$에 대한 귀납법 — 강의에서 끝까지 완결됨).** 명제 $P(n)$: "$x,y$가 $n$비트 음이 아닌 정수일 때 `multiply`는 정확히 $xy$를 반환한다."

- **기저 사례** ($n\le3$): 초등 알고리즘을 쓰므로 자명.
- **귀납 단계** ($n\ge4$): $x_1, x_0, y_1, y_0$은 각각 최대 $\lceil n/2\rceil$비트이므로 $x_1+x_0$과 $y_1+y_0$은 각각 최대 $\lceil n/2\rceil+1$비트다. $n\ge4$이면 $\lceil n/2\rceil+1 < n$이 성립하므로(예: $n=4$이면 $2+1=3<4$), 귀납 가정을 $p_1$에 대한 재귀 호출에 적용할 수 있어 $p_1=(x_1+x_0)(y_1+y_0)$. 마찬가지로 $x_1,y_1$과 $x_0,y_0$은 각각 최대 $\lceil n/2\rceil$비트로 $n$보다 엄격히 작으므로 귀납 가정에 의해 $p_2=x_1y_1$, $p_3=x_0y_0$. 따라서
$$p_2\cdot2^n+(p_1-p_2-p_3)\cdot2^{n/2}+p_3 = x_1y_1\cdot2^n+(x_1y_0+x_0y_1)\cdot2^{n/2}+x_0y_0 = xy,$$
즉 반환값이 정확히 $xy$와 같아 증명이 완성된다. $\blacksquare$

**기저 사례를 왜 $n\le3$으로 잡았는가 (교수가 이 증명 도중 되짚은 이유).** 만약 기저 사례 기준을 $n\le2$로 낮췄다면, $n=3$은 더 이상 기저 사례가 아니라 귀납 단계가 되는데, 이때 $\lceil 3/2\rceil+1 = 2+1 = 3 = n$이 되어 **엄격한 부등식이 깨지므로** 귀납 가정을 적용할 수 없다. 기준을 $n\le3$으로 잡아야 $n\ge4$인 모든 귀납 단계에서 $\lceil n/2\rceil+1<n$이 항상 성립한다 — 이것이 §C에서 언급된, 처음엔 기억나지 않는다고 했던 그 이유다.

### E. Algorithm 3의 실행시간 — $O(n^{\log_2 3})$, 그리고 마스터 정리 적용의 미묘한 결함과 보정

**점화식과 마스터 정리.** 결합 단계(분할, 최종 덧셈/뺄셈, 시프트)는 여전히 선형이므로 어떤 상수 $c>0$에 대해
$$T(n) = 3T(n/2) + cn.$$
$a=3,b=2\Rightarrow\log_b a=\log_2 3\approx1.585$. $f(n)=cn=\Theta(n)=O(n^{\log_2 3-\epsilon})$을 예컨대 $\epsilon=0.5$로 두면 만족하므로 경우 1에 해당해
$$T(n) = \Theta(n^{\log_2 3}) = O(n^{1.59}).$$
즉 $\Theta(n^2)$였던 §C(4-way)보다, 그리고 그래드스쿨 알고리즘의 $\Theta(n^2)$보다도 실제로 개선된다. (참고: 교수는 시험에는 마스터 정리 명제 자체가 첫 페이지에 주어지므로 암기할 필요는 없다고 언급했다.)

**적용상의 결함.** 마스터 정리는 재귀 호출 크기가 정확히 $n/2$의 floor 또는 ceiling이어야 한다고 요구한다. $p_2, p_3$에 대한 호출(각각 $x_1,y_1$과 $x_0,y_0$)은 이 조건을 만족하지만, $p_1$에 대한 호출은 그렇지 않다 — $x_1+x_0$과 $y_1+y_0$은 자리올림 때문에 최악의 경우 $\lceil n/2\rceil$보다 **1비트 더 길** 수 있다. 따라서 엄밀히는 추가 논증 없이 위 점화식 형태를 그대로 주장할 수 없다.

**보정 (교수가 "step\*"라 명명).** 실제로는 이 문제를 다음과 같이 우회할 수 있다: $x_1+x_0$과 $y_1+y_0$ 전체를 재귀 호출에 넘기는 대신, 각각의 **최상위 비트(자리올림으로 생긴 초과 비트)를 따로 떼어내고, 남은 정확히 $\lceil n/2\rceil$비트만 재귀 호출에 넘겨** 그 부분의 곱을 구한다. 그런 다음 떼어냈던 최상위 비트가 1인 경우에 대해 (그 비트에 해당하는 상대편 정수를 적절히 시프트해서 더해주는) 선형 시간의 추가 연산을 수행해 $(x_1+x_0)(y_1+y_0)$의 참값을 복원한다. 이렇게 하면 재귀 호출의 입력 크기가 정확히 $\lceil n/2\rceil$비트 이하로 마스터 정리의 요건을 그대로 만족시키면서, 추가 비용은 여전히 선형이라 점화식 자체는 바뀌지 않는다. 교수는 또한 이런 보정 없이 원래 버전(최대 $\lceil n/2\rceil+1$비트를 그대로 재귀 호출에 넘기는 버전)을 쓰더라도 실행시간이 여전히 $O(n^{\log_2 3})$임을 증명할 수 있다고 언급했지만, 그 증명은 강의에서 보이지 않았다.

**결론.** Algorithm 3은 $O(n^{\log_2 3}) \approx O(n^{1.585})$ 시간에 정수 곱셈을 정확히 계산한다 — §B의 그래드스쿨 알고리즘($\Theta(n^2)$), §C의 4-way 분할정복($\Theta(n^2)$)보다 점근적으로 더 빠르다.

### F. 마무리 — 새 알고리즘 설계 기법 예고 (서울→부산 호텔 비용 문제, cliffhanger로 종료)

분할정복 논의를 마무리하며 교수는 "다음 알고리즘 설계 기법"으로 넘어간다고 예고했다(기법의 이름은 이 시점에 언급되지 않았다 — 이 노트는 추측하지 않는다). 도입한 예제 문제:

**문제.** 서울(도시 $C_0$)에서 부산(도시 $C_n$)까지 여행한다. 도시 목록 $C_0, C_1, \dots, C_n$과, 연속한 두 도시 사이의 거리 $d_i = \mathrm{dist}(C_{i-1}, C_i)$가 입력으로 주어진다(도시 개수 $N$ — 혹은 그보다 1 적은 값 — 도 입력으로 주어진다; 교수 본인이 이 부분을 약간 모호하게 남겼다). 걷거나 자전거로 이동하며, 하루에 이동할 수 있는 최대 거리 $D$가 주어진다 — 예컨대 $d_1+d_2+d_3 \le D$이면 첫날에 $C_0$에서 $C_3$까지 이동할 수 있지만, 이를 초과하면 안 된다. 도시 $i$에서 묵으면 호텔비 $p_i$를 낸다. **목표: 하루 이동 거리가 $D$를 넘지 않으면서 서울에서 부산까지 가는 총 호텔비를 최소화.** (마지막 도시 부산에서 묵는 비용을 내는지 여부와 무관하게 답에 차이가 없으므로 $p_n := 0$으로 두고 논의를 단순화 — 어느 쪽으로 봐도 결과는 같다.)

**Algorithm 1 (매우 비효율적인 첫 시도).** 재귀 함수 `generateSchedule(k)`: $D$ 제약을 지키는지 여부와 무관하게 처음 $k$개 도시에 대해 **가능한 모든 일정**(각 도시에서 잘지 말지의 모든 조합)을 생성한다.
```
function generateSchedule(k):
    if k == 0:
        return { "" }                        # the singleton set containing the empty schedule
    S ← generateSchedule(k-1)
    S' ← ∅
    for each schedule s in S:
        S' ← S' ∪ { s + "skip", s + "stay" }  # branch on sleeping at city k or not
    return S'

# main: candidates ← generateSchedule(n+1)
#       filter to schedules respecting the daily distance limit D
#       return the one with minimum total hotel cost
```
**정확성은 자명하지만(모든 경우를 실제로 다 만들어보므로) 지수 시간이다.** 교수는 이를 "재귀 호출 횟수"가 아니라 **"호출 사이에 오가는 정보의 크기"** 관점에서 설명했다: 이 재귀 함수 자체는 $n, n-1, \dots, 0$으로 딱 선형 횟수만큼만 호출된다 — 호출 횟수만 보면 나쁘지 않다. 그런데 한 호출에서 다음 호출로 반환되는 값(가능한 일정들의 집합)의 **크기 자체가 지수적으로 크다** — 이것이 이 알고리즘이 비효율적인 진짜 이유라는 것.

**다음 시간으로 이월된 목표.** "여전히 재귀적인 알고리즘을 원하지만, (1) 함수가 너무 많이 호출되지 않아야 하고, (2) 호출 사이에 오가는 정보의 실제 크기도 작게 유지해야 한다 — 효율적인 알고리즘을 기대하려면 먼저 이 두 가지가 필요하다"는 질문을 남기고 시간이 다 되어 강의가 끝났다. **이 문제의 해법 자체는 다음 강의로 명시적으로 이월되었다 — 이 노트는 추측하지 않는다.**
